# Структура бази даних проекту (newdb.db)

Даний проект використовує реляційну модель бази даних, що складається з 4 взаємопов'язаних таблиць для забезпечення ефективної логістики та моніторингу.

## 📋 Огляд таблиць

### 1. `tasks` — Завдання
Центральна таблиця для керування логістичними процесами.
- **Призначення:** Зберігає інформацію про замовлення на переміщення дрона.
- **Ключові поля:** - `sender_id` (замовник)
  - `from_location_id` (точка відправлення)
  - `to_location_id` (точка призначення)
  - `status` (стан виконання)

### 2. `locations` — Локації/Точки
Довідник усіх фізичних точок маршруту.
- **Призначення:** Зберігає назви або координати майданчиків для зльоту та посадки.
- **Оптимізація:** Використання ID замість текстових назв підвищує швидкість роботи бази даних.

### 3. `users` — Користувачі/Оператори
Реєстр суб'єктів, які мають доступ до системи.
- **Призначення:** Ідентифікація людей або систем, що створюють завдання.
- **Безпека:** Дозволяє вести звітність та відстежувати, який саме оператор ініціював завдання.

### 4. `safety_logs` — Журнал безпеки
Технічний лог стану навколишнього середовища.
- **Призначення:** Автоматичний запис даних з датчика газу MQ-2.
- **Функція:** Дрон працює як "екологічний патруль", фіксуючи рівень забруднення в кожній точці маршруту.
